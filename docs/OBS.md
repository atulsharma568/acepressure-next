# OBS + Aitum Vertical

## Before changing scenes

Export your current Scene Collection and make a copy of `D:\Stream Assets\AcePressure`. The package does not modify either automatically. `Migrate_OBS.bat` creates backups and a separate JSON if you choose to use it. See MIGRATION.md.

In the new system, a tip starts on your public tipping page. A direct transfer using the old static UPI QR has no pending request and is normally ignored. Replace that QR in your scenes with a **QR to the public tipping page**, generated by `Generate_Page_QR.bat`, once your HTTPS hostname is stable.

## Horizontal tip alert

1. Start the server and sign in to Admin → OBS.
2. Copy **Horizontal alert** URL. In OBS create a Browser Source named `AcePressure Tips - Horizontal`.
3. Uncheck **Local file**; paste the URL; set width **2560**, height **1440**, FPS **30**.
4. Set source position to x=0, y=0 and reset its transform if needed. The overlay itself places the card near the top center.
5. Keep OBS's transparent browser CSS (the overlay has a transparent body). Enable **Control audio via OBS** if your OBS build offers it.
6. Add the same existing source to every horizontal scene that needs it, rather than creating separate browser instances. Keep **Shutdown source when not visible** off and **Refresh browser when scene becomes active** off if you want the queue continuously consumed. Understand the visibility tradeoff below.
7. Admin → Alertbox → Test alert. It displays `TEST ALERT — NO MONEY RECEIVED` and cannot change totals.

## Aitum vertical tip alert

Create a separate browser source named `AcePressure Tips - Vertical` in your Aitum vertical layout using **Vertical alert** URL:

- width **1080**, height **1920**, position x=0/y=0, 30 FPS.
- URL has `layout=vertical&audio=0` by default.
- Reuse that source within vertical scenes.

Both channels receive the same verified tip, and each channel plays one alert at a time. OBS gets them first: while an OBS browser source is connected, a normal browser tab with the same link shows “Preview only” and takes no alerts, so a forgotten tab can't swallow them.

- The dashboard and the Activity Dock show which alert overlays are connected, for example “Alert overlays · Horizontal: OBS ✓ · Vertical: not connected”. A red line means a normal browser tab is taking alerts: close it. An amber line means two OBS sources compete for one layout: use one source per layout and add it to every scene.
- Admin → OBS gives each overlay an **OBS on this PC (recommended)** link, which keeps alerts working if Tailscale drops. Sources you already added keep working, so there's nothing to change.
- Other streaming apps (not OBS): add `&claim=always` to the alert link. Without it, a normal browser tab takes alerts only while it is visible and no OBS source is connected.

### Prevent double audio

Horizontal audio is on, vertical audio is off by default. Route the single horizontal audio into the desired stream audio mixes. If your vertical output is isolated and needs its own audio, enable vertical `audio=1` only after arranging independent audio mixes; otherwise viewers or recordings may hear echoes. Browser sources in separate outputs are not automatically isolated audio buses.

When **Control audio via OBS** is enabled, verify that the source's audio meter moves and the correct streaming track is selected in Advanced Audio Properties. Avoid monitoring back into Desktop Audio unless you deliberately prevent duplication. Test your exact OBS/Aitum routing before streaming.

## TTS engines

AcePressure makes the Edge, Piper, Windows and Azure audio itself (Edge and Piper since 1.6.0) and the OBS source just plays it, so OBS needs no installed voice. Only **Browser voices (OBS)** depend on the voices available inside OBS. Admin → TTS shows what happened to the last OBS readout.

### Browser

Uses `window.speechSynthesis`, with `en-IN` / `hi-IN` defaults. It depends on the browser engine's installed voices. An OBS Chromium build may expose no usable speech voices even when your normal browser does. Browser speech may also not route through OBS the same way as media audio. This is why a Windows WAV alternative exists.

### Windows SAPI (recommended if available on your streaming PC)

1. Run `List_Voices.bat`. It lists the SAPI voices and cultures actually accessible to PowerShell/System.Speech.
2. In Admin → TTS, choose `windows` and set the allowed voices array to exact listed names or cultures, for example `["en-IN"]` **only if present**. Some Windows voices are OneCore-only and are not visible to System.Speech; installing a Windows language pack does not guarantee this adapter can use it.
3. Test a short message, then one in Hindi if an appropriate listed voice is installed. If no Hindi voice is listed, do not advertise Hindi support until you install/verify one. Hinglish pronunciation depends on the voice and spelling; natural delivery is not guaranteed.
4. The backend renders text as a WAV with the fixed `scripts/Speak.ps1` script. Viewer text is passed as JSON stdin, never interpolated into a shell command. OBS plays the WAV as HTML audio. Rendering is serialized and capped by a timeout; a failure does not verify or alter a tip.
5. Test through the actual OBS source with its audio mixer enabled. Windows SAPI was not executable in the Linux build/test environment.

`off` disables speech. TTS minimum, character limit, allowed voices and filter terms are configurable. `Mute TTS` stops current speech and prevents upcoming speech. `Skip TTS` stops the current utterance; it does not delete the donation. Failed/unsupported speech leaves `tts_played` false. The stored flag indicates completed playback acknowledged by a browser, not proof that OBS broadcast or the viewer heard it.

## Goals

Create one or more goals in Admin → Goals. No permanent default target is seeded. Each goal has its own ID and direct URL in Admin → OBS:

```text
/overlay/goal?goal=GOAL_ID&key=YOUR_OVERLAY_KEY
```

Use width **700**, height **180** for one compact goal; increase height if you display several without the `goal` selector. The larger design suits BRB/Chatting. Progress style can be solid or segmented. Weekly resets use Monday at midnight IST. Monthly/daily resets change the query window, never delete donations. Carry-forward goals start at the configured date; custom end dates are exclusive. The starting amount is added to every automatic period, so leave it at zero unless you intentionally want that recurring offset.

Legacy goal source size was 700×82. A source that small now shows a compact card (title, amounts and bar, no percentage line); resize it to 700×180 for the full widget. `Migrate_OBS.bat` sets 700×180 for you. Inspect scene transforms after migration and do not assume the old crop/scale still fits.

## Leaderboard and recent tips

- `/overlay/top3?period=stream&design=compact&key=...`
- `period=today`, `week`, `month`, or `lifetime` are also supported.
- Compact: **700×260** as a starting canvas, enlarge to 700×300 for longer names.
- BRB/Chatting: `design=large`, **900×500**.
- `/overlay/recent?key=...`: **700×400** for all five recent tips. A source shorter than 370 px shows the latest three instead of cutting a row in half.

These sources update every 1.5 seconds. Public overlays include names, messages and display amounts only; never emails, bank references or raw SMS.

## Activity Dock

OBS → Docks → Custom Browser Docks (wording can vary by OBS version):

- Name: `AcePressure Activity`
- URL: `https://YOUR-HOST/obs/activity` (local HTTP works before secure-cookie deployment).
- Sign in with your admin password inside the dock; it uses a different browser cookie store from your normal browser.

The dock shows connection status, today's/stream totals, top supporters, latest verified/manual tips, replay, mute/block, skip alert, skip TTS and test alerts. Do not capture this private dock into your stream scene.

## Going live (1.6.4)

When OBS starts streaming, the alert source tells AcePressure and a stream session starts, unless one is running or you switched it off in Admin → OBS → **When OBS goes live**. The source needs Page permissions (in its Properties) at the default, **Read access to OBS status information**, or higher. A tip made just before the session started still gets its alert when the payment arrives.

Sessions never end by themselves. When OBS stops streaming, the dashboard and the dock show “OBS stopped streaming” with **End session**. If you end a session while OBS is live, refreshing the source doesn't start a new one for 2 hours; going live again does. The overlay key can start a session but never end one. Aitum Vertical streaming on its own doesn't start a session.

## Skip alert (1.6.4)

**Skip alert** stops the alert on stream on both layouts: the card leaves and its sound, video sound and voice stop. A layout that hasn't shown it yet never will. It acts on the source's next status check, within about 2 seconds. **Skip TTS** stops only the voice. Blocking a supporter also stops their alert on stream.

## Delivery limitations and behavior

- Automatic alerts only arise from a newly verified tip created in the currently active stream session. Off-session tips remain history and goal support but do not automatically alert. A manual correction requires explicit Replay to alert.
- Queued events expire after five minutes, so a browser opened hours later will not replay an old backlog. Use Replay in the dashboard if needed.
- A claim is leased. A crashed source can retry after the lease expires; exactly-once visual/audio delivery across crashes is not guaranteed. If a crash occurs after display but before acknowledgment, a retry may repeat the alert. Revenue is still idempotent.
- `alert_shown` means the browser acknowledged a completed presentation. An invisible but running OBS source can acknowledge an alert. The browser cannot prove the scene was on-air.
- Ending a session cancels queued events and stops speech on the next state poll. A card already visible may finish its short animation.
- Sound and TTS can be blocked by browser autoplay/voice availability. The visual alert and ledger stay functional. Verify audio in OBS, not only a normal browser.
- Which sound plays: a viewer's pick plays first, otherwise your default from Admin → Sound library, or the alert video's own sound when that is your default. If a picked clip can't load, the default plays instead (Chime, when the default is the video's own sound); if the video's own sound can't play, Chime plays. The vertical source is silent by default (`audio=0`). **▶ Test on stream** in Sound library checks one sound in OBS. After upgrading, refresh an old source once (right-click it → Properties → **Refresh cache of current page**) so 30-second sounds aren't cut at 21 s.
- Keep overlay URLs private: their key grants public-safe overlay reads and queue playback acknowledgment, not admin or credit-verification powers. Rotate it via the maintenance tool if exposed.
