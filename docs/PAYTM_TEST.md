# Paytm iPhone capture test (version 1.0.3)

This feature is intentionally capture-only. Even an exact match to a pending tip
never verifies it, changes totals, or creates an alert. It is disabled outside
DEMO_MODE. The existing SMS verifier still requires a transaction reference.

## Update the existing Windows installation

1. Stop Start_Demo.bat using Ctrl+C in its running window.
2. Back up the entire existing AcePressure folder to a separate folder. This
   preserves .env, data-demo, data, existing overlays and settings.
3. Extract the new ZIP into a separate folder. Copy its `acepressure` folder
   into your existing AcePressure folder, accepting replacement of code files.
   Also copy VERSION and docs/PAYTM_TEST.md. Do not replace .env, data,
   data-demo, or .venv. No dependency reinstall is required for this update.
4. Run the existing Start_Demo.bat. Sign in at http://localhost:8766/admin.
5. Open http://localhost:8766/admin/paytm-test in the same browser.

## Give the iPhone a temporary HTTPS address

The iPhone's localhost is the phone, not the PC. Keep the PC server on 127.0.0.1.
Install cloudflared using the official Windows download instructions:
https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/
Open a terminal where cloudflared.exe is available, then run:

```
cloudflared tunnel --url http://127.0.0.1:8766
```

Keep this window running. It prints an https://...trycloudflare.com address.
That temporary address exposes the demo web service; keep admin credentials private.
Do not share the URL with viewers. No router port-forwarding is required.
The address changes when the tunnel restarts. This is a development tunnel, not
the eventual production deployment. If cloudflared reports an existing config
conflict, resolve it without deleting your existing tunnel configuration.
Official reference: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

## Configure the iPhone Shortcut

Keep the existing Paytm notification trigger. Initially test with no filters so
we can establish exactly which title/body fields contain the credit wording.
Only the notification generated by the chosen app supplies the input; app choice
in Shortcuts is not a bank signature and the server cannot independently attest it.

1. On the PC's private Paytm test page, click Start 30-minute capture. A random
   capture-only token appears in a masked field. Show it only when copying it
   privately to your iPhone. Do not send the token or a screenshot of it in chat.
2. In the Shortcut, add a Text action containing the full **Notification variable**
   (not literal text and not Associated Content). This converts it to text.
3. Add Get Contents of URL. Set its URL to the temporary HTTPS address followed
   by `/api/bridge/paytm-test`. Method: POST. Request Body: JSON.
4. Add header `Authorization` with value `Bearer YOUR_CAPTURE_TOKEN` (one space).
   Add `Content-Type` with value `application/json`.
5. Add a JSON text field named `text`. Its value must be the output variable of
   the Text action above. Do not manually type the word Notification.
6. Optional: add `notification_date` as text, using the notification's Date
   property formatted as ISO 8601. Never use Current Date as a retry identifier.
   It is not required for the first connectivity test.
7. Replace the old Show action with Show Result using the output of Get Contents
   of URL. The diagnostic Show Notification action can stay temporarily.
8. Allow the requested network permission. First test unlocked. Then replace
   interactive Show Result with Show Notification containing the response and
   test with the phone locked. An unattended POST has not been proven until the
   private dashboard records that test.

On success the response says `mode: capture_only`, `verified: false`,
`alert_created: false`, and `amount_paise` (e.g. 1137 means INR 11.37).
The private PC page refreshes automatically. Duplicate equal input increments
`repeats`. Unsupported text is recorded as unrecognized, never as a payment.

401 means expired/stopped/wrong capture token. Start again and replace the token
in the Shortcut. Server restart disables capture. 404 can mean wrong address,
old code, or running the live server instead of demo. 429 means rate limited.
When finished, click Stop capture and close the tunnel window.

## Limits and privacy

- No real UPI transaction reference has been observed in Paytm notifications.
  A private keyed fingerprint detects repeated input, not a bank transaction.
  Identical legitimate receipts may collide; changed notifications may not dedupe.
- Notification delivery can fail or be delayed. Paise precision and locked-phone
  operation require tests on the actual phone. Neither is assumed to work.
- Names, bank suffixes and raw notification text pass through HTTPS for this test
  but are not stored or logged. Only amount, outcome, arrival time, fingerprint
  and repeat count persist in the diagnostic table. No public endpoint lists it.
- Records are bounded to 500 and purged after seven days on list/ingest access.
  Existing database backups can retain these metadata longer.
- No live Paytm verifier is enabled by this feature. Authenticated phone reports
  are not provider-signed receipts. Missing or ambiguous evidence must be handled
  by an explicit admin bank check, not automatically labelled bank verified.
